# SHA-1 Signin

1. open android folder in Android Studio - Importing gradle android project - Sync Gradle with Android Files step -
   Gradle configuration phase - Reads settings.gradle, Resolves included projects (like :react-native-safe-area-context)
   Gradle resolves React Native native modules , eg. includeBuild("../node_modules/react-native-safe-area-context/android")

2. cd android
./gradlew signingReport

3. Generate Signed Apk / Bundle after successful Sync. Signed APK for device deploy, Signed bundle for App store deploy

Debug and release builds with keystore. inside - android/apps - Running Gradle Build => Generates signed APK

Keystore - Keystore is a binary file = digital signature or ID card for your app.
Reason - 
1. Google Play requires all apps to be digitally signed. This verifies the identity of the developer.
2. Updates: This is the most critical part. Once you upload an app signed with a specific key, all future updates must be signed with the exact same key.
3. Apk update in the existing app works using : 
The Package Name (The ID): com.tradeo - When you try to install a new APK with this same ID, Android recognizes it and asks: "Do you want to update this existing application?"
The Keystore (The Security Check): Once you click "Yes" to update, Android checks the Keystore signature. If keys match -> update else "App not installed" 

4. Customize signinConfigs in android/app/build.gradle
debug.keystore - the "Dummy" id, standard file generated by Android tools - Purpose: Used automatically during development (when you run npx react-native run-android).

5. Verify that you are enforcing correct keystore for debug and release

5. cd android
./gradlew signingReport 

Note => We are using same keystore files for debug and release, While generating this file in Android Studio, We have selected debug option. There is nothing such that on selecting debug, the file is marked as debug and we cannot use in release. These options are just for creating different fingerprints for debug and release variant of our app.


#  Preset and plugin
   A preset is bundle of multiple Babel plugins, pre-configured for a specific environment. 
   A plugin is single, focused code transformation that does something specific.
